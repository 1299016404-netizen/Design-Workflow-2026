# Specification-Driven Generation

<!-- scope: 规格驱动生成；状态表读取、模板分组、语义地图、桥接、diff、轻量复制 -->

## 适用

用户提供状态输入表、执行表或等效结构化状态定义时读取本文件。此模式不推导状态，专注于读懂参考稿并精准变形。

不得同时执行探索式状态矩阵推导。

## 1. 读取状态规格

读取状态总览，确认：

- 本次生成范围：全部或指定状态 ID。
- 每个状态的状态类型：业务状态 / 内容边界状态 / 异常状态。
- 每个状态的结构形态。
- 内容单元及业务意图。
- 推荐方案及理由。
- 主操作、降级规则、互斥和备注。

如备注中存在会影响画稿结果的问题，写入前集中确认。

状态输入表只定义 WHAT：内容存在 / 缺失和业务含义；布局 HOW 由 skill 基于参考稿自动推导。

解释状态表时必须遵守：

- 内容单元按业务含义理解，不要求它们直接对应设计组件名。
- 只把状态表中的业务意图桥接到设计字段，不反向推翻用户已定义的状态范围。
- 推荐方案单独处理，不得混在普通内容单元里；推荐标记必须落到被推荐的子结构上。
- “同参考态”表示结构和字段沿用参考稿，只处理该状态中显式变化的单元。
- 降级规则、互斥和备注只在影响画稿结果时进入写入前确认；纯说明不扩大状态范围。

## 2. 模板分组

读完状态表后必须先分组，未分组不得进入逐状态生成。

- 结构形态相同的状态归为同一模板组。
- 每组选结构最复杂或内容单元最多的状态作为模板状态。
- 同组其他状态标记为轻量复制。
- 结构形态唯一的状态独立作为模板状态。

同模板组内的轻量复制状态不重新做完整语义地图和桥接，只 clone 模板状态节点并 override 文本 / 字段。

## 3. 参考稿语义地图

生成前必须读取参考 Figma 节点。先用 `scripts/read_reference_structure.js` 的 `shallow` 模式读取浅层语义地图，再只对目标模块关键节点使用 `deep` 模式。

若用户输入包含 Figma `node-id`，该节点是唯一目标锚点。需要确定 Page 时，只能遍历 Page 并验证该 `node-id` 可访问；不得用不带 `node-id` 的页面列表、当前画布选择、同名节点或历史补全 Section 反向改写目标。

语义地图必须判断参考节点的承接层级：

- 目标是完整页面：生成态必须复制完整页面并改造目标模块。
- 目标是页面内模块：默认复制真实父页面 / 父容器，把目标模块状态放回原位置验证承接效果。
- 目标是独立组件：生成 component / component set 或组件变体。
- 只有用户明确要求“只生成模块态 / 只看模块”时，才允许输出孤立模块。

语义地图必须输出：

```text
参考节点：file_key / node_id
对象类型：页面 / 模块 / 组件
子结构清单：名称 / 节点 ID / 类型 / 语义角色
组件实例清单：实例名 / main component / variant properties
稳定区：所有状态不变的结构
可变区：按状态变化的结构
```

命中内容边界或结构变体时，额外记录：

- 父容器宽高、内容区宽高、padding、gap。
- 原卡片数量、宽高、间距、图片区和文本区比例。
- 页面流对象、固定底栏、悬浮入口和安全区。
- 关键 Auto Layout 容器的 `layoutMode`、`layoutSizingHorizontal`、`layoutSizingVertical`、`primaryAxisSizingMode`、`counterAxisSizingMode`、padding、itemSpacing、子节点顺序。
- 关键文本节点的 `textAutoResize`、文本框宽高和换行 / 截断策略。

同一参考节点 / 同一模板组只深读一次，不得每个状态重复深读。

读取字段白名单：

- `shallow`：`id/name/type/visible/x/y/width/height/layoutMode/childCount/childrenNames`，以及一层可见子节点摘要。
- `deep`：仅目标模块关键节点，以及为页面承接必需的直接父容器、直接后继页面流对象、固定区外层；必须包含 layout sizing、textAutoResize、padding、itemSpacing、componentSet 和 variant 信息。
- `probe`：只返回路径可用性和风险摘要；目标节点、clone 源、页面流、固定区、关键 Auto Layout 容器分别返回少量命中结果即可。
- 禁止默认读取：实例内部矢量、图片像素、导航图标细节、状态栏细节、不可见装饰层完整 children。
- 禁止默认返回：全页 Auto Layout 容器列表、全页完整 children tree、无关稳定区详细几何、完整 instance 内部树。

## 4. 路径探针

结构变体或 clone 改造前，必须用 `scripts/read_reference_structure.js` 的 `probe` 模式验证：

- clone 后关键节点路径是否稳定。
- 目标模块是否可按名称 / 语义找到。
- 下方页面流和固定区能否识别。
- 关键 Auto Layout 容器是否可读取。

探针只返回 `ok/foundNodes/missingPaths/flowObjects/fixedObjects/autoLayoutContainers/risks`，不返回完整几何树。`flowObjects`、`fixedObjects`、`autoLayoutContainers` 必须限制为目标模块承接相关的少量节点；若只能通过全页扫描发现，应先返回候选摘要，再定向 deep，不得把全页扫描结果直接作为正式上下文。

## 5. 模板状态生成

每个模板状态执行：

1. 桥接：把内容单元业务意图映射到语义地图中的子结构 / 字段。
2. Diff：列出保留、删除、替换、新增。
3. 组件来源确认：新增结构优先来自参考稿或同文件其他状态，其次 manifest；找不到则降级或阻断。
4. 布局策略：命中内容边界、页面流或结构变体时读取 `references/layout.md`，并形成 sizing plan，明确哪些节点继承 Fill / Hug / Fixed，哪些节点因结构变体需要改变。
5. 写入：按 `references/figma-write.md` 执行，优先 clone 参考页面 / 模块 / 组件后改造，不得从空白重画近似卡片。
6. QA：按 `references/qa.md` 执行，问题清零后才能进入下一个模板组。

桥接门禁：

- 每个内容单元必须对应语义地图里的目标子结构、字段或明确的新增来源。
- 字段归属按槽位判断，不按视觉位置或文字相似度硬对标。
- 推荐理由必须先判断推荐的是哪个服务 / 权益 / 卡片，再落到该行或该卡；不得借用其他高亮槽位承载。
- 稳定字段不得被状态文案覆盖；如需联动变化，必须说明联动关系。

## 6. 轻量复制状态

同模板组的非模板状态：

- clone 同组模板状态。
- 只 override 差异字段：标题、说明、推荐文案、价格、标签、锚点信息、CTA 等。
- 不改变结构，不重新做完整桥接。
- 简化 QA：检查文本 override、推荐归属、旧语境残留和明显视觉破坏。

如果轻量复制中发现结构需要变化，必须升级为新的模板状态。

## 7. 批量生成

同一批状态尽量一次 brief、一次 compose、一次 use_figma 写入。成功返回轻量结果；失败时只展开失败状态和相关节点证据。失败修复不得回到全量结构读取，除非错误证明浅读阶段漏掉了关键目标模块。
