# Layout Rules

<!-- scope: 页面组合态、页面流顺延、固定区域、内容数量边界、超长内容、模块高度变化、视觉组、Auto Layout 保真 -->

## 适用

仅在以下场景读取：

- 状态会改变完整页面的导航、tab、列表数量、模块位置、主行动或页面可见区域。
- 目标模块高度、数量或显隐变化会影响下方页面流内容、浮层标签、列表项位置。
- 核心变化来自数量、文案长度、图片缺失、字段缺失、展示上限或信息密度。
- 横纵布局切换、结构变体、Auto Layout 保真。

普通文案 override、字段值变化和纯显隐状态不默认读取本文件。

## 1. 页面流联动

- 模块状态默认在真实页面 / 父容器中验证承接效果，不得只画孤立模块后声称页面级 QA 通过。
- 写入完整页面组合态前，建立后续页面流对象清单：目标模块之后的列表项、依附标签 / 浮层 / 价格说明、固定底 bar、悬浮入口和安全区。
- 模块高度、显隐或内容数量变化后，若下方对象属于页面流，应按 `新 y = 上一对象 y + 上一对象实际高度 + 原 gap` 重新排布。
- 依附对象必须跟随所属对象移动，不得只移动卡片本体导致标签、浮层、角标脱离。
- 固定底 bar、悬浮入口和安全区通常保持位置，除非原页面结构表明它们属于普通页面流。
- 若用户要求“页面其他内容不动”，但模块收缩会产生明显大空白，应在 Figma 写入前暂停确认：保留原位、按页面流顺延，或只生成模块态。

## 2. 完整页面组合

- 页面级状态必须用完整页面呈现，保留头图、导航、背景、核心模块和关键上下文，不要只画缩略线框。
- 页面组合态优先复制主页面或主模块实例，优先切换 variant，再做必要 override。
- 复制原页面模块后，如果父容器是 Auto Layout，必须检查子节点顺序；不能只改 y 坐标。
- 改结构时标记为 `结构变体`，并保留原色彩、圆角、字体层级、图文风格和关键装饰关系。
- 如果只在孤立模块内完成布局，但未放回页面 / 父容器验证下方承接，不得判定为完整通过。

## 3. 内容边界判断

- 先识别内部元素类型、数量上限、互斥关系和优先级，再生成合法组合矩阵。
- 状态输入表只提供内容边界，不提供布局答案。数量减少后的父容器策略、卡片结构、图片 / 文本比例、模块高度和页面流联动，必须由 skill 根据 Figma 参考稿自动推导并直接执行。
- 必须区分排布能力和展示能力。容器可以 wrap 不代表下一行一定展示。
- 空状态必须判断删除模块还是保留占位；无占位要求时删除空容器并让下方内容上移。
- 保留项不应默认取前 N 个，应根据业务优先级、主页面重点和用户决策价值选择。
- 内容数量减少时，不得只删除多余元素或等比例拉伸剩余元素；必须重新判断剩余元素内部的信息排布、横纵向空间利用和模块高度自适应。
- 如果减少到单个或少数元素后出现右侧 / 下方无效空白、内容集中在左上角、关键字段被拆成不必要的多行，应生成结构变体，而不是沿用原多元素布局。
- 判断结构变体时优先聚合强关联字段，例如名称、价格 / 优惠、勾选 / 状态图标、CTA 等；宽度增加时应利用横向空间让关键决策信息更集中，辅助说明可独立成行。
- 内容减少到 1 / 2 项时，不得默认居中剩余元素；必须先判断父级模块的信息阅读轴。信息卡、会员卡、订单卡、列表卡等以左侧扫描为主的结构，应优先保持左侧起始轴和紧凑信息组；只有独立主视觉、结果反馈、空态图形或状态徽章等语义才优先考虑居中。此规则适用于内容单元在父容器内的排布位置。内容单元内部元素的对齐方式属于内部布局，应在结构变体的内部布局推导中独立判断，不受此规则机械覆盖。
- 横排重组后必须继续检查父容器高度、模块主内容区高度和下方行动区位置。若内容高度减少且父级允许收缩，应同步收缩权益区 / 内容区 / 行动区位置，避免只改子元素而保留旧高度。
- 当状态规格出现 `1排N`、`N项`、`数量边界`、`可用数量=1/2` 等结构形态，且目标模块处于完整页面的固定宽父容器内，写入前必须明确父容器策略：生成适配整行宽度的结构变体、同步收缩父容器并联动页面流，或只生成模块态。不得只收缩子模块或删除子卡片，把固定宽父容器的剩余区域留成可见空白。
- 保留原视觉语言不等于保留原内部布局。颜色、字号、圆角、基础间距可稳定，但信息排布、文本框高度、卡片高度和模块高度应随内容边界重新适配。

## 4. 布局策略自动推导

命中内容边界布局时，写入前必须先在内部完成布局策略自动推导；除非出现产品决策或结构归属歧义，不需要人工确认。

自动推导必须读取并判断：

- 父容器：宽高、内容区、安全边距、是否固定宽、是否 Auto Layout、是否 clipsContent。
- 原子项：原数量、单项宽高、间距、图片区、文本区、标题区、说明区、CTA / 状态图标。
- 自适应关系：父容器、列表、卡片、信息组、标题行、说明文案分别是 Fill / Hug / Fixed，文本是否 `textAutoResize=HEIGHT` 或 `WIDTH_AND_HEIGHT`。
- 视觉组：主视觉组、主信息组、辅助信息组、操作组、状态 / 标签组等，及其组内阅读轴和组间对齐轴。
- 内容密度：剩余内容在新宽度下的行数、文本实际高度、图片和文字占比、可视空白占比。
- 模块高度：卡片高度、推荐区 / 内容区高度是否需要随内容减少而收缩。
- 页面流：目标模块之后哪些对象属于普通页面流，哪些属于固定底 bar、悬浮入口或安全区。

自动推导的默认决策：

- 多列到双列：优先使用完整内容区等分或紧凑双列；若高度和信息密度仍合理，可保留原卡片纵向结构，但必须重新计算卡片宽度、文本框宽高和模块高度。
- 多列到单卡：不得只把单张原卡拉到整行后保留原高度。必须优先判断紧凑重点卡、横向图文卡、摘要卡或父容器收缩模块态；若文本在新宽度下单行或少行展示，应同步压缩文本区、卡片高度和模块高度。
- 若整行适配会造成单卡内部大面积空白，应改为紧凑结构并收缩模块高度，而不是继续扩大卡片。
- 若父容器收缩或模块高度收缩会影响下方内容，应同步移动页面流对象；不能只改目标模块内部。
- 结构变体必须以视觉组包围盒为单位计算位置。先确定组内阅读轴和组间对齐轴，再落到节点坐标；不得沿用旧节点局部坐标或孤立硬编码偏移作为主要布局依据。
- 结构变体写入脚本应优先嵌入或等价实现 `scripts/layout_visual_groups.js`，并返回组级 `layoutQa`。
- 结构变体必须同步产出 sizing plan：默认继承参考稿 Fill / Hug / Fixed；只有尺寸语义确实变化时才声明改变原因。不得为了方便 `resize()` 把可编辑容器或文本从 Hug / Fill 隐式改成 Fixed。

### 内容单元内部布局重推导

结构形态变化不仅影响容器级排布，也会改变单个内容单元的空间语境。当结构变体导致内容单元的形态发生质变时（例如纵向卡片变横向图文卡、窄卡变宽卡、多行信息区变单行），必须基于新的空间比例和阅读方向，对内容单元内部元素重新推导布局，而不是机械沿用原形态的内部排列。

质变判断标准：
- 内容单元主轴方向改变（纵→横或横→纵）。
- 内容区宽度变化超过原宽度的 50%。
- 内容单元内部从多行堆叠变为单行并列，或反之。

命中质变时，内部布局重推导必须覆盖：
- 元素分组关系：哪些元素同行、哪些换行、哪些堆叠。
- 组内对齐轴：标题组、说明组、操作组各自的水平/垂直对齐方式，应基于新形态下元素自身的视觉语义独立判断，不受容器级排布规则（如父容器阅读轴）的机械覆盖。
- 文本区宽高：文案在新宽度下的实际行数、文本框高度。
- 信息密度：新空间下元素间距、留白比例是否合理。

不命中质变时（如只是等比缩放、同方向微调宽度），沿用原内部布局即可。

视觉组与 Auto Layout 的关系：

- 视觉组模型用于推导组间关系、目标尺寸和阅读轴，不等于最终 Figma 节点结构。
- 落地到 Figma 时，必须把视觉组关系翻译成 Auto Layout 属性：父容器方向、子节点顺序、padding、gap、fill / hug / fixed 和必要的绝对定位例外。
- 参考稿中可编辑的 Auto Layout 容器不得因为视觉组布局通过而被降级为 `layoutMode = "NONE"`。
- 参考稿中可编辑节点的 `layoutSizingHorizontal`、`layoutSizingVertical`、`primaryAxisSizingMode`、`counterAxisSizingMode` 和文本 `textAutoResize` 也是 Auto Layout 保真的一部分；生成稿未经声明不得从 Fill / Hug / Auto resize 退化为 Fixed。
- 结构变体写入脚本必须同时返回视觉组 `layoutQa` 和结构保真 `autoLayoutQa`。截图目检和视觉组 QA 不能替代 Auto Layout 结构 QA。

只在以下情况暂停询问用户：

- 用户明确要求页面其他内容不动，但布局规则判断模块应收缩或页面流应上移。
- 原稿疑似横滑 carousel / 可滚动容器，少项时是否仍保留滑动语义无法从 Figma 判断。
- 0 项状态没有说明是隐藏模块、保留空态还是保留入口。
- 下方对象无法判断是普通页面流、固定区、悬浮区还是安全区。
- 有多个同等合法的组件 / 结构来源，无法从参考稿、状态表和设计系统判断优先级。

## 5. 超长内容

- 超长状态必须真实触发换行、截断或溢出边界，不要缩短成普通单行。
- 优先保留原模块 Auto Layout、原组件实例和原子节点顺序，只调整文本框宽高、最大行数、截断和必要容器高度。
- 标题 + 标签共用横向 wrap 容器时，继承自然换行逻辑：剩余宽度不足时才换行。
- 如果手动模拟换行或绝对定位，必须先测量当前字体下的真实文字宽度，再截图确认没有空洞、孤行、叠字或裁切。

## 6. 数量边界

- 不要只删除多余卡片或等比例拉伸剩余卡片，应根据状态重排布局。
- 多列到双列：可保持原卡片结构，但要重新分配宽度、文案行数、内容区高度和模块高度。
- 多列到单卡：优先判断是否切换为横向图文、重点卡或摘要卡。
- 多列到单卡时，写入前必须完成单卡密度预判。若单卡铺满父容器后，图片区 / 文本区之外空白成为主要视觉面积，或说明文案少行但卡片高度仍接近多卡态，应直接生成紧凑宽卡、横向图文卡、两行信息卡或摘要卡；不得先生成低密度大卡再依赖截图后修复。
- 完整页面态中，父容器宽度固定时，1 排 2 / 1 排 1 必须优先适配父容器宽度生成结构变体；若保留原卡片宽度紧凑排列，必须同步收缩父容器并处理页面流，或改为模块态。
- 多列到少列时，若卡片宽度显著增加，必须检查卡片内部是否应从纵向堆叠改为横向信息行；例如将名称、金额、状态图标同行承载，以减少无效空白并提升屏效。
- 多列到少列时，间距不应为了填满整行而被拉大；若剩余项属于同一信息组，应按父级阅读轴紧凑排列，让用户一眼扫完。
- 删除项后，同一行可见空白大于一个原卡片宽度，或剩余内容不足原行宽约 70%，且没有业务占位说明时，必须视为无效空白，重新布局或阻断交付。
- 单卡状态即使父容器已被填满，也必须检查卡片内部可视空白；如果图片和文本之外的空白成为主要视觉面积，或标题 / 说明只占很小区域而卡片高度保持原多卡高度，必须判为低密度大卡并重新生成紧凑结构。
- 如果说明文案在新宽度下可单行展示，不应继续保留多行文本框高度；模块整体应按实际内容高度收缩。
- 内容减少后，下方模块应按页面流重新排布；固定底 bar、悬浮入口和安全区通常保持原位置。

## 7. QA 要点

- 完整页面组合态必须同时截图检查目标模块局部和整页可见区域。
- 检查模块下方大空白、列表断层、依附标签错位、固定区域误动。
- 检查无右侧无效空白、行内空洞、单个徽标孤立成行、叠字或裁切。
- 数量边界状态必须截图检查父容器整行；局部节点宽度正确但父容器留白明显，仍判为失败。
- 数量边界状态必须截图检查卡片内部密度和模块高度；父容器不留白但卡片内部低密度、大面积空白或模块未收缩，仍判为失败。
- 结构变体必须检查视觉组包围盒、组内阅读轴和组间对齐轴；节点宽高和文案都正确但视觉组漂浮、偏移或错轴，仍判为失败。
