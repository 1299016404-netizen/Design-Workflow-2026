# Core Rules

<!-- scope: 探索式推导；对象层级、状态范围、变量、矩阵、候选确认、异常态边界 -->

## 适用

用户没有提供完整状态输入表，只提供 Figma 参考稿、需求背景或“补齐全状态 / 全情况”诉求时读取本文件。

规格驱动生成不得读取本文件来重新推导状态。

## 1. 对象层级

先判断状态发生在哪一层：

- 页面级：导航、tab、列表数量、主流程、上下游链路变化。
- 模块级：卡片、权益模块、订单模块、推荐模块等整体状态。
- 子结构级：标题区、价格区、CTA 区、权益行、活动行、提示区。
- 字段级：名称、价格、地址、规则文案、标签、图片、图标等内容边界。

矩阵主轴必须来自目标对象本身，不要用笼统业务概括替代真实变量。

## 2. 状态范围分流

用户未指定状态类别或具体状态时，默认进入全状态范围确认。先基于当前对象轻量分析，再动态给出 A/B/C 选项：

- A. 业务全状态：资格、时间、参与、权益、交易、库存、可用性等会影响用户决策或主流程的变量。
- B. 内容边界状态：0 / 1 / 多个 / 超上限、长文案、缺字段、缺图、信息密度变化等会影响布局承载的变量。
- C. 异常状态：loading、骨架屏、空态、网络失败、权限失败等平台基础异常。

低层交互状态和极端异常状态只有用户明确点名时才展开。异常状态除非用户明确要求，否则最多在矩阵中标注由平台基础规范覆盖，不展开画稿。

用户已明确状态类别时，直接按指定类别执行，不再反问范围。

## 3. 变量识别

对目标对象列出可组合变量：

- 类型：有哪些子元素或业务字段。
- 数量：0 / 1 / 多个，是否有展示上限。
- 互斥：哪些状态、类型、variant 不能同时出现。
- 优先级：空间不足时谁先展示，谁后置、折叠或裁切。
- 长度：文案、价格、地址、标签是否有长 / 超长状态。
- 可用性：可用、不可用、部分可用、已使用、资格未满足等。
- 时间 / 进度：未开始、进行中、已结束、即将过期、结果已产生等。

先列组合，再过滤不成立组合和低价值组合。

变量必须来自目标对象本身。抽象解释可以保留，但不能替代真实字段成为矩阵主轴。

展示策略判断：

- 删除：该结构无业务意义且没有占位规范。
- 收缩：内容减少且父容器允许页面流顺延。
- 增高：内容需要完整展示，且原模块允许页面流顺延。
- 折叠 / 后置：低优先级内容空间不足。
- 占位：规范要求布局稳定或异步加载时保留空间。

必须区分排布能力和展示能力。容器可以 wrap 不代表下一行一定展示；如果高度固定且裁切开启，不能机械增高容器。

## 4. 候选状态确认

生成候选状态后，必须让用户确认具体生成范围。未经确认，不得写入 Figma；除非用户明确回复“全部生成”。

命中 A/B/C 组合时按分组展示，不要平铺成长列表：

```md
根据你选择的状态类型，我推导出以下候选状态。你希望这次生成哪些？

**A. 业务全状态**
| 编号 | 状态 | 核心变化 |
|---|---|---|

**B. 内容边界状态**
| 编号 | 状态 | 核心变化 |
|---|---|---|

**C. 异常状态**
| 编号 | 状态 | 核心变化 |
|---|---|---|

你可以回复编号，例如 A1、A3、B2，或回复“全部生成”。
```

普通多候选状态确认格式：

```md
我推导出以下候选状态。你希望这次生成哪些？

| 编号 | 状态 | 核心变化 |
|---|---|---|

你可以回复编号，例如 1、2，或回复“全部生成”。
```

面向用户确认的表格只保留编号、状态、核心变化。触发条件、用户含义、生成方式和不适用组合保留在内部矩阵。

## 5. 矩阵字段

内部矩阵至少包含：

- 状态名称
- 状态类别
- 触发条件
- 用户含义
- 页面 / 模块 / 子结构变化
- 主 CTA
- 生成方式：原组件覆盖 / variant 切换 / 结构扩展 / 仅进矩阵
- 是否画稿
- 不适用组合与过滤原因

矩阵是写入前门禁：凡是会改变是否画稿、模块构成、展示内容、CTA、页面结构或字段显隐的不确定项，必须在写入前问清楚。

## 6. 组件复用预检

写入前检查：

- 主页面已有 component / component set / instance。
- 核心模块实例、main component 和 variant properties。
- 哪些状态可通过切换 variant 覆盖。
- 哪些需要新增 variant。
- 哪些只能结构扩展或仅进矩阵。

组件来源不足时不得输出正式高保真稿，可降级为低保真并说明。

## 7. 稳定字段锁定

生成前列出稳定字段，避免状态补齐误改：

- 业务稳定信息：酒店名、房型名、店铺名、活动名、权益名、基础价格结构。
- 视觉稳定组件：按钮样式、图标、徽标、标签样式、圆角、分隔线。
- 布局稳定关系：原 gap、padding、下方模块位置、固定底 bar、安全区。

只有目标对象相关字段可以变化。其他字段如需变化，必须说明它与该状态的联动关系。

## 8. 场景拆解规则

- 页面级状态必须保留页面上下文，不能只生成模块缩略图。
- 模块级状态优先生成模块全情况，必要时补页面组合态验证承接。
- 子结构级状态优先复用原组件实例和原槽位。
- 字段级状态优先处理内容边界，避免误改模块业务状态。
- 异常状态只有用户明确要求时才展开；未明确时只在矩阵中标注由平台基础规范覆盖。
