## 酒店域

### 酒店详情页会员表达模块（二官卡）

核心业务变量：

- 开通状态：未开卡 / 激活账号 / 注册中 / 已开卡 / 会员失效。
- 成长状态：无房晚积分 / 有房晚积分 / 即将升级。
- 挑战状态：挑战任务中。
- 权益数量：4 / 3 / 2 / 1 个。
- 权益可享性：可享 / 不可享。
- 活动行状态：有活动 / 报名成功 / 无活动。

飞猪特有决策：

- 账号开通链路（未开卡→激活→注册中→已开卡→失效）和成长进度链路（房晚积分→即将升级）是独立业务流程，必须分开建模。
- 该类模块必须同时补"子组件变体"和"页面中模块状态"。

### 酒店 rate 权益强化表达

核心业务变量：

- rate 类型：房型 rate / 普通 rate。
- 权益类型：免费早餐 / 无忧退 / 会员专享价 / 积分或里程抵扣。
- 表达阶段：权益强化前 / 权益强化后。
- 承载字段：早餐字段 / 退改政策字段 / 运营坑标 / 服务标签 / 价格利益点。

飞猪特有决策：

- 免费早餐类权益优先落在早餐字段，其次同步运营坑标。
- 无忧退类权益优先落在退改政策字段，其次同步运营坑标或服务标签。
- 无忧退权益后态的运营坑标保持 F4 无忧退，强化表达落在退改政策文案。
- 房型 rate 和普通 rate 布局密度不同，不能直接复制房型 rate 画法到普通 rate。
- 稳定字段：酒店名、店铺名、价格结构、按钮样式。可变字段：运营坑标、早餐、退改政策、服务标签、价格利益点。

## 出行服务域

### 多服务推荐列表页字段归属

飞猪 App 中常见"多服务推荐列表"页面（如出行方式推荐、综合服务推荐），以下字段归属规则适用于此类页面：

服务行字段归属：

- 服务名称槽：只承载当前服务品类名称。
- 服务地点槽：只承载当前服务自身的执行地点、取还点、集合点或覆盖范围。不得把旧路线、筛选条件、目的地或行程路径拼入服务地点。
- 服务推荐理由槽：只解释当前服务为什么被推荐，不得承载模块级状态、订单级提醒或 Tab 级提示。
- 价格 / CTA 槽：保持同类槽位，基线、间距、状态和可点击语义正确。

推荐理由归属：

- 推荐理由必须先判断"推荐的是哪一个服务"，再落到该服务行。
- 同组服务中只有一个服务被推荐时，推荐理由只能在该服务行承载。
- 不得为了复用已有高亮信息行而把推荐理由放到另一个服务行。
- 没有明确推荐原因来源时，可使用同服务标准源、同业务默认规则或中性说明；仍无法判断时列为不确定项。

路线 / 筛选槽处理：

- 路线 / 筛选槽只在当前状态仍需要用户选择路线或筛选条件时保留。
- 新场景不需要该槽位时，必须删除并同步收缩布局。

Clone 继承规则：

- 从旧服务行 clone 时，每个继承子节点都必须重新归类业务角色。
- 无法归类到新状态字段的继承文案、文字链、行动入口或辅助说明必须删除。
- 价格、数量等数值字段必须有明确来源，不得从旧服务或相邻行随意继承。

## 活动权益域

飞猪特有决策：

- 活动承接页要先判断单活动 / 多活动、单商家 / 多商家、是否需要 tab 或列表，再进入挑战卡矩阵。
- 同一商家下可承载多个活动时，应先判断单活动和多活动的页面级结构差异。
