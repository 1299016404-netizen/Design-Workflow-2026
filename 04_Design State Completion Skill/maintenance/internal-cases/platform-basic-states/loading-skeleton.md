# 样例：酒店权益模块 Loading 骨架态

## 背景

页面业务背景是酒店详情页中的权益介绍模块。主页面已完成深色背景的酒店权益展示：标题区、两侧装饰分割线、4 个权益 icon 容器和 4 个权益名称。需求不是补业务全情况，而是测试在没有手动全情况输入时，能否读取平台级 loading / 骨架规范，并生成该模块的 loading 骨架态。

该案例属于明确点名的平台基础状态。虽然 `figma-design-completion` 默认不重点展开通用 loading / 异常态，但当用户明确要求时，应将范围收敛到指定基础状态，不扩写无关网络失败或空态。

## 主页面输入

主页面包含：

- 深色卡片容器，尺寸 `702×260`，圆角 `24`。
- 内容容器，`x=53 y=30 w=596 h=200`。
- 标题区，`x=118.5 y=30 w=465 h=42`。
- 标题文本，`x=186 y=30 w=330 h=42`。
- 权益列表，`x=53 y=102 w=596 h=128`。
- 4 个权益项，每项 `104×128`，列间距 `60`。
- icon 容器，`80×80`，圆角 `24`。
- 权益文案 text frame，`y=194 h=36`。

## 平台规范读取

初始检索问题：

- 只用 `loading skeleton 骨架屏 加载 占位` 这类混合关键词，没有召回 Fliggy Style 中的 `骨架型`。
- 远程导入 `骨架型` 组件后，只读取到示例资产结构，组件 `description` 和 `documentationLinks` 为空。
- 组件本身不包含完整规范说明文字，不能等同于已读取平台规范。

正确读取路径：

- 对 `Fliggy Style` 分别检索 `骨架`、`骨架型`、`加载`、`通用型`、`下拉型`、`图片型`。
- 命中同组资产：`01 通用型`、`02 下拉型`、`03 图片型`、`骨架型`。
- 用户提供源文件节点 `Fliggy Style / 13 加载 Loading` 后，读取源规范页文字，而不是只导入组件实例。

源规范页中的骨架型规则：

- 颜色：`color-bg（#F2F3F5）`。
- 圆角：一般为 `6px`；原先设计稿就存在的矩形，与原先保持一致。
- 动画：保持统一，进行呼吸闪动。
- 透明度：`100%-40%-100%` 循环动画。
- 速度：`1s / 个循环`。

## 生成版本复盘

### v1：按常识生成，未真正读取平台规范

问题：

- 当前文件和已订阅库的初始搜索没有命中规范组件，就直接按通用骨架常识生成。
- 误把“没有搜索到”表述成近似“规范不可用”。
- 未识别到 Fliggy Style 中存在 `骨架型`。

经验：

- 平台规范搜索必须拆关键词，尤其中文组件名不一定包含 `loading` 或 `skeleton`。
- 未命中不能直接推导为没有规范，应扩大到源规范文件或请用户提供规范页。

### v2：读取到组件资产，但仍缺完整说明

改进：

- 命中并导入 `Fliggy Style / 骨架型`。
- 读取到示例资产的骨架块色值 `#F2F3F5` 和圆角约 `5.4px`。
- 在补全区加入规范资产引用。

问题：

- `骨架型` 只是示例组件，组件节点无完整说明文字。
- 仅根据组件实例推断规范，遗漏了颜色、圆角、动画等文字规则的完整上下文。

经验：

- 远程组件的 `description` 为空时，必须继续读取源规范页。
- 组件资产引用和规范文字读取是两件事，不能互相替代。

### v3：读取源规范页，补齐完整说明

改进：

- 读取用户提供的 `Fliggy Style / 13 加载 Loading` 源文件节点。
- 抽取完整规则：颜色、圆角、动画、透明度范围和循环速度。
- 在 Figma 补全区写入完整说明、状态矩阵、骨架态和透明度对照样例。

问题：

- 几何细节仍有偏差：标题区骨架总宽 `436`，原稿为 `465`；权益文案骨架高度 `28`，原稿文案 frame 高度为 `36`。

经验：

- 读取规范后仍要回到原稿几何复查。骨架态的占位块应对齐被替代元素的 frame，而不是只看视觉大致比例。

### v4：几何复查版

修正：

- 标题区总宽修正为 `465`。
- 标题骨架宽度修正为 `330`。
- 权益列表保持 `596×128`。
- 权益项修正为 `104×128`。
- 权益文案骨架高度从 `28` 调整为 `36`。

验收方式：

- 用脚本对比原稿和生成稿的关键几何值：标题区、权益列表、icon 容器、文案占位。
- 截图确认骨架块没有裁切或错位。

### v5：深色背景机动映射版

背景：

- Fliggy Style 的 `#F2F3F5` 是白色背景上的骨架规范色。
- 当前酒店权益模块是深色渐变卡片，直接套用 `#F2F3F5` 会过亮，像真实内容块或按钮，破坏深色模块语境。

修正：

- 保留平台规范的结构、圆角和呼吸透明度规则。
- 将标题 / 文案骨架映射为 `#334057 @95%`。
- 将 icon 面骨架映射为 `#253149 @100%`。
- 将分割线骨架映射为 `#334057 @65%`。
- 动效仍按 `100%-40%-100%`，`1s / 循环`。

最终验收：

- V5 被确认可用。
- 生成区域未覆盖 V1-V4，保留了迭代过程。

## 可复用规则

- 用户明确要求平台基础状态时，应收敛到指定状态，不因 skill 默认范围而跳过。
- 设计系统检索要拆关键词，中文规范尤其要检索短核心词，如 `骨架`。
- 示例组件不是完整规范。必须优先读取源规范页的说明文字、同组类型和适用场景。
- 规范色值不是无条件套用。若规范语境和当前模块背景冲突，应保留规范意图，对颜色做有说明的机动映射。
- 骨架态生成必须进行几何复查：标题区、列表区、icon 容器、文案 frame 高度都要和原稿对齐。
- 版本迭代应不覆盖旧稿，方便复盘失败点和验收最终可用版本。
