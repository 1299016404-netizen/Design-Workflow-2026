# 样例：航司会员挑战活动承接页

## 背景

页面业务背景是航司商家面向会员开放会员挑战活动。每个商家的挑战在一个页面中承接，一个商家下可以有多个挑战活动。用户达到报名要求后可报名，完成对应任务后获得奖励。

## 主页面输入

主页面包含：

- 头图 banner
- 挑战 tab
- 挑战卡
- 奖品中心
- 活动规则
- 页面背景

## 人工全情况目标

补全重点：

1. 商家下有多个挑战
2. 商家下单个挑战
3. 挑战卡全情况
4. 不同挑战类型下的不同参与状态

## 页面级场景

必须考虑：

- 商家下有多个挑战
- 商家下单个挑战

判断规则：

- 多挑战：需要挑战 tab 或多个挑战卡
- 单挑战：可去掉 tab，挑战卡直接前置

## 挑战卡矩阵

任务类型：

- 单次任务
- 单进度任务
- 多阶梯任务

参与状态：

- 未参加
- 挑战中
- 挑战成功
- 挑战失败结束
- 不可报名

特殊规则：

- 单次任务不生成“挑战中”
- 多阶梯任务需要展示阶段进度
- 单进度任务需要展示当前进度
- 未参加状态主 CTA 通常为“立即报名”
- 挑战中状态主 CTA 通常为“去完成”或“去订票”
- 挑战成功状态突出结果和奖励
- 挑战失败结束状态弱化 CTA，强调结果
- 不可报名状态突出不可报名原因
- 可报名态不应展示“剩余50天”，应展示报名时间
- 挑战中态应展示挑战剩余时间和继续完成任务的行动点
- 成功、失败、不可报名均不展示主按钮

## 输出组织方式

推荐 Figma 区域：

- `业务状态补全 / 航司会员挑战活动`
  - `00 状态矩阵`
  - `01 页面级场景 / 多挑战`
  - `01 页面级场景 / 单挑战`
  - `02 挑战卡全情况`

需要人工确认的问题不默认写入 Figma，只在最终回复中给出。

页面级状态必须用完整页面表达，不要只画缩略线框。完整页面应保留头图、导航、背景、奖品中心、活动规则和页面级模块顺序。

挑战卡全情况建议按矩阵摆放：

- 横轴：参与状态
- 纵轴：任务类型

横轴：

- 未参加
- 挑战中
- 挑战成功
- 挑战失败结束
- 不可报名

纵轴：

- 单次任务
- 单进度任务
- 多阶梯任务

## 对比复盘结论

从自动精修版和手动全情况稿对比得到：

- 页面级状态和模块级矩阵都必须保留。
- 页面级状态应是完整页面，不是抽象线框。
- 挑战卡必须优先复制原组件实例并切换 variants。
- 卡片状态变化不能只改状态标，还要同步时间文案、辅助说明、行动点和按钮显隐。
- 挑战名称、任务标题、奖品名称、会员等级名称是稳定字段，不随参与状态变化。
- 判断字段类型优先看图层名和组件层级，不要只看当前文案。
- 生成前必须检测可加载中文字体，`PingFang SC` 不可用时优先用 `Noto Sans SC`。
