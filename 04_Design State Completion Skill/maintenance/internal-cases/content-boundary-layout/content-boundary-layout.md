# 样例：酒店会员详情页推荐权益数量布局

## 背景

页面业务背景是酒店会员详情页。权益模块顶部有一块推荐权益模块，主页面已完成 `1排3` 推荐权益布局。需求是补齐 `1排2` 和 `1排1` 的推荐权益布局，并且三种状态都以完整页面呈现。

该案例属于酒店会员域中的内容边界状态，重点不是会员资格变化，而是推荐权益数量变化引发的布局智能适配。

## 主页面输入

主页面包含：

- 会员卡详情完整页面。
- 会员卡头部。
- 会员专属活动。
- 权益模块。
- 推荐权益：当前为 `1排3`。
- 普通权益组。
- 底部旗舰店入口。

## 盲测阶段结论

在未读取手动全情况前，正确推导应包括：

- 状态发生在页面级，因为用户要求完整页面呈现。
- 核心变化发生在 `权益 / 推荐权益` 模块。
- 需要生成 3 个完整页面状态：推荐权益 3 个、2 个、1 个。
- 推荐权益卡不是组件实例，而是页面内 frame 组合，因此应复制原页面和原卡片结构改造，不应新造视觉样式。

## 状态矩阵

| 状态名称 | 状态类型 | 触发条件 | 页面变化 | 生成方式 |
| --- | --- | --- | --- | --- |
| 推荐权益 3 个 | 页面级基准态 | 推荐权益数量为 3 | 保持原 1 排 3 卡 | 原页面覆盖 |
| 推荐权益 2 个 | 页面级布局态 | 推荐权益数量为 2 | 推荐权益改为双列短文案卡，模块高度压缩 | 复制完整页面 + 重排推荐权益 |
| 推荐权益 1 个 | 页面级布局态 | 推荐权益数量为 1 | 推荐权益改为左图右文重点卡，下方权益组上移 | 复制完整页面 + 重排推荐权益 |

## 自动生成版本复盘

### v1：状态覆盖正确，但布局适配过于机械

v1 做到了：

- 生成 3 个完整页面状态。
- 复用原完整页面和推荐权益卡 frame。
- 没有覆盖原主页面。

主要问题：

- `1排2` 只是拉宽卡片，仍保留原 311 高度和过长描述区，没有压缩成双列短文案。
- `1排2` 默认保留前两个权益，漏掉手动稿中更高优先级的 `迎宾赠礼`。
- `1排1` 只是把上图下文卡拉宽，没有改为单卡更合理的横向图文结构。
- `1排1` 误把底 bar 当成页面流内容上移，和手动稿的固定底部入口策略不一致。
- 调整标题区时一度把标题两侧装饰符推到卡片边缘，说明卡片内部装饰元素需要跟随标题成组居中。

### v2：按内容边界做布局智能适配

v2 修正为：

- `1排2`：双列短文案卡，卡片 `345×280`，推荐权益模块高度 `280`，权益组上移。
- `1排2`：保留 `客房升级` 和 `迎宾赠礼`，不默认取前两个。
- `1排1`：横向重点卡，左图右文，推荐权益模块高度 `163`。
- `1排1`：权益组上移，但底 bar 保持固定位置。
- 右侧内容区需要从原纵向 auto layout 改为自由布局或横向布局，否则坐标会被自动布局拉回。

## 可复用规则

- 数量型补齐不是机械删卡或拉宽卡片，应判断当前数量下更合理的信息结构。
- 多卡强调并列扫描；双卡可保留卡片结构但压缩文案区；单卡通常应转为重点卡或横向图文。
- 保留对象不默认取前 N 个，应根据业务优先级和用户决策价值选择。
- 模块内部高度可以压缩，但固定底部操作区不一定跟随上移。
- 当布局方向发生变化时，要检查 auto layout 是否会覆盖坐标；必要时切换布局模式。
